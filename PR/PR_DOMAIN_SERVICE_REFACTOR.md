## 📌 refactor : 도메인 모델 고도화 및 서비스 로직 최적화

---

## ✨ 주요 변경사항

| 분류 | 내용 |
| --- | --- |
| **Domain Model** | `Setter` 제거 및 비즈니스 의도가 담긴 메서드(`update`, `addLike` 등) 추가 |
| **Logic** | `getBoardList` 중복 로직 통합 및 `private` 메서드 추출 |
| **Transaction** | 전역 `@Transactional(readOnly = true)` 및 쓰기 메서드 전용 선언 |
| **Persistence** | JPA **Dirty Checking** 활용으로 불필요한 `save()` 호출 제거 |

---

## 🔍 상세 설명

### 1. 빈혈 모델에서 풍성한 도메인 모델로 전환

기존의 서비스 계층에서 데이터를 하나하나 갈아끼우던 방식에서, **엔티티가 스스로 상태를 관리**하는 방식으로 변경했습니다.

* **캡슐화:** 외부에서 알 필요 없는 상태 변경 로직을 엔티티 내부로 숨겼습니다.
* **유지보수:** 좋아요 개수 제한(`Math.max(0, ...)`) 등의 규칙을 엔티티에 응집시켜 비즈니스 로직의 일관성을 확보했습니다.

### 2. 트랜잭션 및 성능 최적화

* **Read-Only 최적화:** 조회 메서드에 `readOnly = true`를 적용하여 하이버네이트 스냅샷 저장 비용을 절감했습니다.
* **변경 감지:** `@Transactional` 범위 내에서 엔티티가 수정됨에 따라 별도의 `repository.save()` 없이도 커밋 시점에 DB 반영이 이루어지도록 개선했습니다.
